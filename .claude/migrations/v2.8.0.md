# Migration to v2.8.0 — the second-brain structure

Applies when updating a project from any template version below v2.8.0. Run by `/template-update` after its file sync. Execute the transformation as a work packet through the `builder` agent (adopted as a role in Codex/Copilot); verify with `doc-sync-check`. Everything here restructures — nothing here rewrites or deletes content.

## What changed structurally

v2.8.0 introduced hub-and-spoke docs (oversized spec/architecture domains get their own pages), the reference shelf (`docs/reference/`), and the decision-log lifecycle. Older projects have flat docs and no shelf.

## Transformation rules (in order)

1. **Create the reference shelf.** Add `docs/reference/README.md` from the template. Scan the archive section of `docs/brainstorm.md` for research briefs still worth reading (cited, still true, decision already made) — move keepers to `docs/reference/<topic>.md` and list them in the shelf table. Everything else stays archived.
2. **Split only what has outgrown its drawer.** For `docs/project_spec.md` and `docs/architecture.md`: under ~150 lines, leave the file whole — this rule then changes nothing. Above that, split by domain/component: move each oversized section **verbatim** to `docs/spec/<domain>.md` or `docs/architecture/<component>.md`, leaving one summary line plus a link in the hub. Move first; improve never (improving content is not a migration's job).
3. **Consolidate the decision log only if it needs it.** Over ~100 lines: fold ratified night-shift rulings older than 30 days into thematic one-liners (`2026-Q3 — [n] naming/copy rulings, all ratified — pattern: [one line]`). Keep verbatim, always: LESSON lines, reversals, house-rule changes, and everything from the last 30 days. Mark superseded decisions; delete nothing.

## Zero-loss verification (mandatory)

Account for every heading and every decision line of the old docs. Each must be **MOVED** (findable at its new path), **MERGED** (named by a consolidation line), or **IN PLACE**. *Deleted is not an outcome.* Report the counts: moved / merged / in place / deleted — and deleted must be 0.

## Verify

Run `doc-sync-check`: hubs and spokes consistent, no dangling links, shelf table matches the files on disk. Then report against the dry-run's promises.
